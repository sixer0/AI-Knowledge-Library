# S6 - Close-out and Knowledge Promotion (general; executor: librarian lane; gate: G4)

Purpose: make the finished record reusable knowledge and keep it fresh, then
capture what the first real run taught about the procedure itself. Identical
for every object class except the register updated (each profile names its
living register).

## Execution checklist
1. Promote the record to the Information Library via gsp-librarian: provenance
   attached, deduplicated against existing IL objects, attestation recorded.
   Save the note in `05-closeout/il-promotion-note.md`.
2. Update the living master register of the class (profile names it; B1: the
   vendor register, DEMS-VSAT class). Trust tier, DD status, dates. Save the
   change record in `05-closeout/master-register-update.md`.
3. Record refresh triggers in `05-closeout/refresh-triggers.md`, at minimum:
   six-month cycle; ownership / funding / acquisition change; sanctions or
   export-list change; the counterparty signs another Indonesian partner or
   equivalent relationship event; before any signature or tender naming. A
   delta re-run touches only affected lanes.
4. First-real-DD validation form (D-06): when this mission is the first real
   DD run of its class, attach `05-closeout/validation-first-arrival.csv`
   filled from templates/validation-first-arrival.md: stage where ambiguity
   appeared, gate tripped (which gate and why), real turnaround vs the user
   deadline per stage, templates that hindered, proposed Rev B text, filler
   account, date. One row per incident; end with counts per stage. This form
   is the input for the next standard revision.
5. Confirm the whole record is indexed: every working file reachable from the
   record annex list.

## Gate G4 predicates
IL promotion note present; master register update recorded; at least four
refresh triggers listed; validation form attached when this is the first real
DD of the class.

## Common pitfalls
- Skipping the validation form because the run "went smoothly". Absence of
  friction is itself a datum; the form records zero incidents explicitly.
- Promoting the record without re-verifying release-bearing fields at close
  time. Promotion is a release surface under SPK-002.
- Refresh triggers written as intentions ("review periodically"). Each trigger
  names its condition and its clock.
