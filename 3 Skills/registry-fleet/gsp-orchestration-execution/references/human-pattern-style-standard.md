# Pembuatan Standar Gaya Tulis dari Pola Manusia (koreksi user D-05, misi GAYA-AHLI-1005, 05-10-2026)

Trigger: keluhan user atas tulisan keluaran fleet ("bertele-tele", "terasa AI", "susunan konteks tidak dipikirkan", "kosakata AI"), atau tugas membuat standar/manual gaya bahasa, proposal, atau buku.

## Vonis koreksi yang mengikat (jangan diulang lagi)

Rencana yang bertumpu pada AMBANG STATISTIK (panjang kalimat, ritme, frekuensi kata) DITOLAK user sebagai salah paham. Yang diminta: MEMPELAJARI CARA MANUSIA PROFESIONAL MENULIS - anatomi seksi, peran paragraf, alur argumen, kosakata yang benar-benar dipakai penulis ahli pada genre sasaran. Metrik tetap boleh ada, jabatannya alat bantu diagnosis, BUKAN sumber aturan. "Mengacak/menyetel kalimat demi angka" = kontradiksi; verifier memvonis FAIL aturan yang dasar angkanya saja tanpa pola diamati. Godaan "optimasi angka metrik" di tengah jalan harus ditolak eksplisit dan dikembalikan ke metode pola-manusia (blueprint GAYA-AHLI menanam penahan ini, dan ia terpakai nyata).

## Kerangka misi yang terbukti jalan (STD-GAYA-AHLI-001 lahir LULUS 15/15 rata 4,00 x4)

1. **Forensik dulu, dengan alat kanonis.** Ukur korpus keluaran sendiri (docx: paragraf + sel tabel; simpan ekstrak .txt). Sapu ulang dokumen yang DULU lolos rilis dengan scanner naturalisasi kanonis - kalau FAIL sekarang padahal dulu PASS, keluhannya kelas T2 (sistem gerbang lemah, hanya tangkap token bukan struktur/suara). Angka forensik jadi sisi "sebelum" di setiap aturan nanti.
2. **RT + TA + lajur genre paralel (gelombang N1).** Lajur riset yang menjawab keluhan per-genre: G1 bedah proposal/KAK/surat/datasheet authored manusia di disk (sumber masukan proyek, BUKAN keluaran fleet); G2 bedah buku teknis (textbook vault + klasik publik); G3 studi kosakata pembanding fleet-vs-manusia + glosarium kendali. Format bukti tiap lajur: kutipan VERBATIM pendek + path + halaman/sel/baris + catatan fungsi retoris. Contoh karangan dilarang jadi bukti (hanya berlabel CONTOH-ILUSTRATIF di luar daftar bukti).
3. **Register POLA-INTI + cek-silang anti-fabrikasi berseed.** Sintesis lintas lajur: tiap pola = pernyataan + >=2 kutipan manusia ber-path + genre asal + kondisi tidak berlaku. VERIFIKASI OLEH CONTROLLER: random.sample(seed tercatat mis. 1005) atas 20 kutipan, normalisasi (lowercase, buang tanda kutip/gabungan spasi), substring-match ke gabungan berkas sumber + dump korpus. 20/20 HIT = register sah dipakai; MISS apa pun = kembalikan ke pekerja, jangan dipertahankan.
4. **Aturan Manual enam bidang wajib** (skema SG-<lapis>-<nn>): (1) pernyataan satu kalimat; (2) fungsi bagi pembaca; (3) BUKTI MANUSIA >=2 kutipan verbatim ber-path; (4) kontras fleet verbatim satu kutipan; (5) predikat verifikasi (angka hanya di sini sebagai ambang bantu berlabel + wajib menyebut pola latarannya); (6) instrumen penegak. Lapis: L0 pembaca / L1 arsitektur / L2 paragraf / L3 kalimat / L4 kata / L5 suara ahli / L6 gerbang.
5. **Rubrik juri + dua juri + adjudikator.** Vonis lepas sah HANYA lewat dua juri independen (bukan penulis), skor 4 dimensi TERPISAH (3 dimensi sasaran user + dimensi penjaga "kesesuaian perilaku dengan pola manusia"), alasan wajib mengutip frasa teks, protokol buta (skor terkunci sebelum melihat skor juri lain/sebelum sisi BEFORE dibuka). Selisih >=2 pada dimensi mana pun -> adjudikator ketiga. Tetapkan tokenizer kata di rubrik sejak awal (cacat F-1: buku ukuran juri tak bisa direproduksi). Kalibrasi genre "naskah standar normatif" eksplisit, kalau tidak, dokumen standar tak pernah bisa lulus vonisnya sendiri (butuh putusan controller tertulis - preseden D-19).
6. **Re-uji tertarget, bukan batch ulang (aturan batch-satu-revisi).** Pasca-revisi: juri menilai ulang HANYA zona yang berubah akibat suntingan bernama; zona tak tersentuh membawa skor lama sah dengan bukti hash zona identik (penulis wajib mencetak pin sha per zona di gerbang revisinya; juri mereproduksi pin dari disk, bukan mempercayai). Cuplikan yang menyusut di bawah lantai karena pemangkasan SAH (menjalankan aturan manual sendiri) -> perluasan jendela berpenanda, jangan menghukum hasil perbaikan (preseden D-20). Batas putaran revisi ditulis eksplisit di kartu (vonis berikutnya gagal sebab-sama -> eskalasi user, bukan Revisi E tanpa ujung).
7. **Mekanisasi L6 lewat jalur tata kelola.** Rekomendasi check scanner baru -> kartu putusan pengelola skill (approve/reject/tunda tertulis per butir, nol menggantung) -> implementasi oleh creator (determinisme dua-run byte-identik, delta check lama nol) -> fixture merah-hijau oleh test-expert (merah harus menangkap, hijau = uji positif-palsu) -> regresi oleh verifier independen atas seluruh korpus. Uji tandingan: cabut tambalan sementara, merah lama harus kembali - membuktikan fixture menguji tambalan, bukan ikut-ikutan hijau. Putusan perluasan whitelist demi positif-palsi nyata boleh (D-17 tanda tangan EN), pelonggaran penagih demi lulus SELALU ditolak.
8. **Retrofit bukti hidup.** Tulis ulang 1 seksi dokumen nyata + 1 sampel surat: before-after berdampingan, penandaan per perubahan -> aturan SG -> pola rujukannya, plus seksi "sengaja tidak diubah + alasan". Gerbang konten-kekal: token tercacah sama dua sisi, ID aturan (mis. DAT-nn) identik, spot fakta terverifikasi - gaya boleh berubah, fakta nol berubah (SPK-002). Ukur pasangan dengan alat yang sama, vonis ke juri buta.

## Pola suara ahli yang terbukti (untuk genre keluaran apa pun di misi serupa)

Ahli menulis KEPUTUSAN (pilih X karena Y, konsekuensinya Z), bukan deskripsi datar; kepala bagian/seksi yang baik MENGAKUI PERTUKARAN ("kerangka menang atas keterbacaan; harganya: suntingan cermin tiap perubahan") dan MENYATAKAN BATASAN faktual - inilah yang membalik skor dimensi "kesan mendalam" 3->4 di tiga zona terakhir. Identifier mesin telanjang di prosa (snake_case kolom, kode gerbang tanpa label manusia) adalah fingerprint AI terkuat; pembuka kalimat berupa nama kolom skema juga. Kode internal hanya sah setelah penjelasan manusia/di tabel berlabel.

## Ops controller selama misi kelas ini

- Worker mati karena limit bridge TEPAT SETELAH artefak lahir (terjadi 3x di misi ini): ukur sendiri artefak dengan parser independen (SG vs outline, bidang lengkap, glif, baris penutup utuh) lalu force-done ber-bukti; JANGAN restart dari nol (menimpa artefak = preseden 03-09). Mitigasi kartu berat berikutnya: --max-runtime 3600 + short check diminta DI AWAL kerja, bukan di akhir.
- Kartu re-juri/re-uji WAJIB berisi gerbang SHA langkah-0 (hitung sha objek; kalau masih versi lama, blok kind=dependency jujur). Dispatcher bisa mengklaim kartu hilir sebelum hulu lahir meski edge terpasang pasca-create (kartu lahir ready).
- Watcher in-memory: daftar ID beku saat proses jalan; setiap gelombang baru = kill + tulis berkas watcher baru + start ulang. Jangan pakai `link <(echo)` dsb. di command gabungan - parser hardline menolak payload aneh; pisahkan perintah.
- Catatan infrastruktur (T6, 06-10): claim kartu dari source_status=review oleh profil yang selalu-memuat skill tak terdaftar crash <65 detik berulang ('Unknown skill(s): sdlc-review' di gsp-skill-manager). Kerja kartu tidak rusak; controller menutup dengan vonis sendiri ber-bukti. Sebelum mengandalkan jalur review-claim, cek skill referensi profil pengklaim ada di disk.
- Penutupan misi: vonis lepas controller ditulis sebagai artefak (f2_vonis-lepas.md) berisi tabel agregasi + putusan butir tertunda (P-n) + suntingan metadata tunggal ber-riwayat (needs-review -> published), lalu F4 adopsi fleet (SOUL marker idempoten, templat TA, katalog skill) + git 3 repo + verifikasi akhir V-* independen, serah sampel ke user sebagai gerbang L3.
